# スマホで税金・国保・年金の支払いを管理する

同期済みの原本はこのリポジトリのMarkdownです。新しい書き込みは先にMacの共有SQLiteジャーナルへ一括保存し、GitHubへ非同期で反映します。画面・MCP・帳簿は未同期分も含む同じビューを読みます。スマホ画面、MCP、Beancount/Favaは同じ請求と支払いを参照します。実際の納税、銀行からの取得、期限の通知は行いません。

## 起動とスマホからの接続

リポジトリのルートで実行します。

```sh
make capture-start
```

表示されたHTTPS URLをAndroidのChromeで開きます。Macで `make capture-key-copy` を実行し、自分の端末間で安全にキーを転送してログインしてください。キーをAIのチャットへ貼らないでください。既存の撮影用キー・セッションを継続使用します。

- URL確認：`make capture-status`
- 停止：`make capture-stop`（MCPとは独立）
- 初回準備：`make capture-setup`
- Chromeのメニューから「ホーム画面に追加」が可能です。
- Macの起動・ネット接続・サーバープロセスが必要です。Macをスリープさせないでください。
- 再起動でURLが変わります。古いホーム画面の入口も更新してください。
- 更新したサーバーコードは再起動後に有効になります。画面は更新ボタンで一覧、ブラウザ再読込でプログラムを読み直します。

## 手元の未払い用紙を登録する

1. 「納付書を登録する」から用紙全体を1枚ずつ撮影するか、保存済み写真を選びます。JPEG・PNG、15MB以下。
2. 写真とOCR候補を照合し、税目、請求元・自治体、課税年度（西暦）、対象期間・所得年、期別、この用紙で払う金額、納期限を確認します。複数候補や読取不能の項目は手入力できます。
3. 用紙が単独で払えることと、記載金額が未払いであることを確認して登録します。不明なら「確認待ちで保存」を使います。金額・請求元が未確認のまま請求を確定することはできません。期限・年度・対象期間・期別は不明のまま保存可能です。
4. 年額の案内・各期の用紙・全期前納の用紙を重ねて登録しないでください。期別の納付書を請求として登録し、年額の案内は既存請求の「関連資料」として保存できます。複数期の案内は代表の請求へ関連づけて参照します。
5. 似た登録がある場合は対象を照合します。同じものなら関連資料として紐づけるか理由付きで除外します。別請求と確認した場合だけ理由を入力して追加します。
6. 「未払い」で用紙の件数・金額・納期限を照合します。期限超過・30日以内（当日を含む）・それ以降・期限未確認に分かれます。金額や既納額が不明な既存レコードは別の要確認枠に出ます。日付の基準は日本時間です。

確認待ちの撮影記録は債務ではなく、残額へ加算しません。支払済みか不明な用紙を未払いと仮定しないでください。請求詳細の「理由付きで訂正」から、確認できた金額・既納額などを履歴付きで補えます。開始時点の既納額には、アプリに登録済みの支払い履歴を含めません。

## 支払った後

1. 対象の請求詳細から「領収書から支払いを記録」を選び、領収済みの証明になる写真を撮ります。
2. 対象・実際の支払日・金額・方法を確認します。納期限を支払日には流用しません。OCRが読めない領収印や日付は本人が確認して入力します。
3. 確認チェック後に確定します。一部払いは残額を更新し、残額0で支払済みになります。過払いになる入力は確定しません。
4. 写真の再送は同じ撮影記録を返します。同日・同額の支払いは重複候補として確認します。再試行後は詳細を見て、既に登録されていないか確かめてください。
5. 転記誤りは支払い履歴の「訂正する」から理由と正しい値を入力します。元の支払いは残し、取消と置換を追記します。取り消すだけの操作も可能です。

未確定または除外済みの写真は「書類の種類・紐づけ先を変更」で、理由を残して納付書／領収書と対象請求を変更できます。同じ写真の再送でも元の紐づけ先を表示するので、その画面から変更してください。確定済みの支払い写真は自動で移動しません。

領収書がない場合は、請求詳細の「明細・本人申告から支払いを記録」を使います。確認元・根拠・実際の金額・支払日を入力し、本人が確認して確定します。予定日を支払い実績として登録しません。

## 請求自体の取消・再開

請求詳細の「請求を取り消す」から理由を入力します。履歴・元の金額を残し、未払い一覧・帳簿・支払いToDoの対象から除外します。「取消済み」タブから確認・再開できます。既納額が不明、または支払い実績が残る請求は取り消せません。実績を照合して先に訂正してください。再開時も重複候補を確認します。

## 保存・同期・復旧

- 「Macに保存済み」は請求・撮影確認・支払いなど関連する変更が、共有SQLiteジャーナルの1トランザクションとして保存された状態です。GitHubやAI Tasksへの接続失敗で失われません。Macのネット接続がなくても、Mac内からの記録は可能です。スマホからMacへ到達するためのネット接続は別に必要です。
- 常駐サーバーはGitHubとAI Tasksへ約30秒ごとに独立して再試行します。通信待ちの間もローカル保存はできます。「同期を再試行」でも処理を起こせます。
- 一覧上部にGitHubへの反映待ち件数とToDoへの反映待ち件数を別々に表示します。GitHubは最後に取得したリモート情報との比較です。
- コードや無関係なファイルの未コミット変更・ステージ済み変更はそのまま保護します。記録の同期コミットに含めません。他の作業の未pushコミットがある場合は、そのコミットを勝手に公開せず同期を止めます。
- 同じ原本ファイルを直接編集した場合、リモート更新や競合がある場合はGitへの反映を止めます。Mac内の保存は残るので、`make records-status` で確認し、別作業を保護して整合させてください。force pushや自動マージはしません。
- ローカルジャーナルを含む検証は `make records-check`。同期は `make records-sync`。Git反映前の原本を生のMarkdownだけで見ると古い場合があるため、AIからはMCPを使ってください。
- 別AI・別画面で同じ原本が変更された場合は更新を拒否します。画面を開き直して最新の記録と照合してください。異なる写真からの同じ請求についても、重複判定と保存を同じロック内で行います。
- ジャーナルとToDo対応表は `~/Library/Application Support/personal-knowledge-mcp/records.sqlite3` と付随するSQLiteファイルにあります。画像保管領域と合わせて本人のMacバックアップ対象に含めます。ジャーナルを削除・初期化して同期問題を解消しようとしないでください。
- 撮影やOCRに失敗しても原画像はMacに残る場合があります。元の写真は端末にも保持し、同じ写真で再試行できます。
- `capture-status` が起動記録との不一致を示す場合は、Macで8780番の待受と撮影プロセスを確認します。停止済みなら `make capture-start` が新しい起動記録を作ります。

## AI TasksのToDoバックエンド

タスクの正本は `personal-ops/ai-tasks` の既存APIです。支払いアプリ内の「ToDo」タブも同じ一覧・更新APIを使い、独自のToDoデータベースを作りません。ローカルジャーナルには請求IDとToDo IDの対応・送信待ち状態だけを持ちます。

ローカルAI Tasksが `http://127.0.0.1:8787` で稼働している場合、`make tasks-connect-local` を一度実行してから支払い・MCPサーバーを再起動します。この設定はGit外に保存します。ローカル認証省略をインターネットへ公開しません。スマホは認証付きの支払い画面を通して操作します。

本番APIを使う場合は `AI_TASKS_URL` にHTTPS origin、`CF_ACCESS_CLIENT_ID` と `CF_ACCESS_CLIENT_SECRET` に既存サービス資格情報を安全に環境変数で渡します。資格情報をチャット・Gitに保存しません。本番バックエンドの構築・配布はpersonal-ops側の運用手順に従います。

- 請求登録から支払いToDoを作成し、納期限変更・完済・請求取消を反映します。作成応答が失われても同じ登録キーと同じ初回内容で再試行し、二重作成しません。
- 支払い原本が完済ならToDoを完了、取消ならToDoを取消にします。進行中など通常の作業状況は保持します。
- ToDoの手動完了だけで支払い実績を作りません。このアプリから未払いに紐づくToDoだけを完了する操作は拒否します。別AIがToDoを完了しても、次の照合で確認待ちに戻し、未払いは残します。
- ToDoの競合・認証切れ・通信失敗は金融記録とは別に保持して再試行します。設定不備でも金融記録の保存はできます。接続設定の変更後はサーバーを再起動します。

画像とOCR全文は `~/Library/Application Support/personal-knowledge-capture/` 内にあり、GitHubには保存しません。Macを失うとGit原本だけでは画像を復元できないため、このディレクトリを本人のMacバックアップ対象に含めてください。画像はログインした本人だけが画面経由で参照できます。

## AIと帳簿

MCPの `list_obligations(status, due_before)` は確認日・期限順の一覧と出典を返します。status は省略、open、unpaid、partial、paid、unknown、cancelled。open等の通常一覧では取消済みを除外します。due_beforeは当日を含むYYYY-MM-DDで、期限不明は指定時に除外します。金額不明を0にせず、通貨を合算しません。全文はUUIDでfetchします。残高は別の確認日時付きスナップショットです。

MCPでの更新もスマホと同じロック・原本検証・ローカルジャーナル保存を使います。fetchのpending_syncは未反映を示します。支払い・訂正履歴は追記式です。MCPサーバーを更新後に再起動するとURL・トークンが変わるため、各AIで再接続してください。ChatGPT/Claudeの接続と検索・取得は各クライアントで実測するまで未検証扱いです。

`make ledger-check` で帳簿を検証し、`make fava` で補助画面を開けます。原本更新後はFavaを再起動してください。取消済み支払いは履歴として原本に残し、現在残高の帳簿投影からは除外します。

## 実物での利用開始確認

Android実機で1枚撮影し、本人が用紙と候補を照合して登録します。スマホ一覧とMCPから同じ金額・期別・期限を取得できることを確認し、残りの用紙を登録して件数を照合します。実際に支払った領収書がある場合だけ支払いを登録します。検証目的で未払いを支払済みにしません。
