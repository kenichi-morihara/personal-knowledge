# スマホで税金・国保・年金の支払いを管理する

原本はこのリポジトリのMarkdownです。スマホ画面、MCP、Beancount/Favaは同じ請求と支払いを参照します。実際の納税、銀行からの取得、期限の通知は行いません。

## 起動とスマホからの接続

リポジトリのルートで実行します。

```sh
make capture-start
```

表示されたHTTPS URLをAndroidのChromeで開きます。Macで `make capture-key-copy` を実行し、自分の端末間で安全にキーを転送してログインしてください。キーをAIのチャットへ貼らないでください。既存の撮影用キー・セッションを継続使用します。

- URL確認：`make capture-status`
- 停止：`make capture-stop`（MCPとは独立）
- 初回準備：`make capture-setup`
- Chromeのメニューから「ホーム画面に追加」が可能です。
- Macの起動・ネット接続・サーバープロセスが必要です。Macをスリープさせないでください。
- 再起動でURLが変わります。古いホーム画面の入口も更新してください。
- 更新したサーバーコードは再起動後に有効になります。画面は更新ボタンで一覧、ブラウザ再読込でプログラムを読み直します。

## 手元の未払い用紙を登録する

1. 「納付書を登録する」から用紙全体を1枚ずつ撮影するか、保存済み写真を選びます。JPEG・PNG、15MB以下。
2. 写真とOCR候補を照合し、税目、請求元・自治体、課税年度（西暦）、対象期間・所得年、期別、この用紙で払う金額、納期限を確認します。複数候補や読取不能の項目は手入力できます。
3. 用紙が単独で払えることと、記載金額が未払いであることを確認して登録します。不明なら「確認待ちで保存」を使います。金額・請求元が未確認のまま請求を確定することはできません。期限・年度・対象期間・期別は不明のまま保存可能です。
4. 年額の案内・各期の用紙・全期前納の用紙を重ねて登録しないでください。期別の納付書を請求として登録し、年額の案内は既存請求の「関連資料」として保存できます。複数期の案内は代表の請求へ関連づけて参照します。
5. 似た登録がある場合は対象を照合します。同じものなら関連資料として紐づけるか理由付きで除外します。別請求と確認した場合だけ理由を入力して追加します。
6. 「未払い」で用紙の件数・金額・納期限を照合します。期限超過・30日以内（当日を含む）・それ以降・期限未確認に分かれます。金額や既納額が不明な既存レコードは別の要確認枠に出ます。日付の基準は日本時間です。

確認待ちの撮影記録は債務ではなく、残額へ加算しません。支払済みか不明な用紙を未払いと仮定しないでください。請求詳細の「理由付きで訂正」から、確認できた金額・既納額などを履歴付きで補えます。開始時点の既納額には、アプリに登録済みの支払い履歴を含めません。

## 支払った後

1. 対象の請求詳細から「領収書から支払いを記録」を選び、領収済みの証明になる写真を撮ります。
2. 対象・実際の支払日・金額・方法を確認します。納期限を支払日には流用しません。OCRが読めない領収印や日付は本人が確認して入力します。
3. 確認チェック後に確定します。一部払いは残額を更新し、残額0で支払済みになります。過払いになる入力は確定しません。
4. 写真の再送は同じ撮影記録を返します。同日・同額の支払いは重複候補として確認します。再試行後は詳細を見て、既に登録されていないか確かめてください。
5. 転記誤りは支払い履歴の「訂正する」から理由と正しい値を入力します。元の支払いは残し、取消と置換を追記します。取り消すだけの操作も可能です。

既存の写真が別の用途・対象に登録済みなら、その記録を確認してください。自動で用途を切り替えたり、異なる請求へ支払いを移したりはしません。

## 保存・同期・復旧

- 「GitHubにも保存済み」は、その操作のcommit・pushが成功したことを示します。画面上部は最後に取得したリモート情報との比較で、常時の通信監視ではありません。
- 「Macに保存済み／同期は要対応」はローカルコミットを保全した状態です。写真を再送して二重登録しないでください。Macで `git status --short` と `git log --oneline origin/main..HEAD` を確認し、必要なコミットをレビューしてpushします。
- 別AI・別画面で変更された場合は更新を拒否します。入力を控えて画面を開き直し、最新の記録と照合してください。
- 作業ツリーが汚れている・リモート更新がある場合は新しい原本保存を拒否します。別作業を保護し、リモート先行なら `git pull --ff-only` 後に再確認します。競合を自動上書きしません。
- 保存中にプロセスが強制終了し未コミットの関連ファイルが残った場合は、Macで差分を照合して検証・復旧してください。画面はその状態で新たな書き込みを続けません。
- 撮影やOCRに失敗しても原画像はMacに残る場合があります。元の写真は端末にも保持し、同じ写真で再試行できます。
- `capture-status` が起動記録との不一致を示す場合は、Macで8780番の待受と撮影プロセスを確認します。他プロセスは停止しません。停止済みなら `make capture-start` が新しい起動記録を作ります。

画像とOCR全文は `~/Library/Application Support/personal-knowledge-capture/` 内にあり、GitHubには保存しません。Macを失うとGit原本だけでは画像を復元できないため、このディレクトリを本人のMacバックアップ対象に含めてください。画像はログインした本人だけが画面経由で参照できます。

## AIと帳簿

MCPの `list_obligations(status, due_before)` は確認日・期限順の一覧と出典を返します。status は省略、open、unpaid、partial、paid、unknown。due_beforeは当日を含むYYYY-MM-DDで、期限不明は指定時に除外します。金額不明を0にせず、通貨を合算しません。全文はUUIDでfetchします。残高は別の確認日時付きスナップショットです。

MCPでの更新もスマホと同じロック・原本検証・Git保存を使います。支払い・訂正履歴は追記式です。MCPサーバーを更新後に再起動するとURL・トークンが変わるため、各AIで再接続してください。ChatGPT/Claudeの接続と検索・取得は各クライアントで実測するまで未検証扱いです。

`make ledger-check` で帳簿を検証し、`make fava` で補助画面を開けます。原本更新後はFavaを再起動してください。取消済み支払いは履歴として原本に残し、現在残高の帳簿投影からは除外します。

## 実物での利用開始確認

Android実機で1枚撮影し、本人が用紙と候補を照合して登録します。スマホ一覧とMCPから同じ金額・期別・期限を取得できることを確認し、残りの用紙を登録して件数を照合します。実際に支払った領収書がある場合だけ支払いを登録します。検証目的で未払いを支払済みにしません。
