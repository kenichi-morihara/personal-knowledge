# 税金・国保・年金の年別管理

- [2026年に支払うもの](2026.md)
- [2027年に支払うもの・2026年分の確定申告準備](2027.md)

税金＋国保・年金を管理する。本人の金額は未確認。年別ページはtype: projectの計画であり、該当未確認の項目や見込みは債務として計上しない。

## 2つの年を分ける

資金繰りの一覧は支払い年（暦年）で分ける。請求原本には対象所得年・課税年度・保険料対象期間や期別を別記する。例えば2026年分の所得税等の通常の確定申告は2027年の支払い管理に関連する。[国税庁](https://www.nta.go.jp/publication/pamph/koho/kurashi/html/06_1.htm)、2026-10-25確認。

## 確認後の登録

1. 通知書・申告書・本人申告・領収書・引落結果で金額、期限、既納額を確認する。自治体、加入区分、消費税の課税状況を推測しない。
2. [支払い義務雛形](../../templates/obligation.md)を使い、finance/taxes配下に1請求1レコードを作る。fiscal_yearには通知書等の年度を入れ、対象所得年・保険料対象期間・申告状況を本文に別記する。
3. 申告期限、納期限、実際の支払い予定日／口座引落日を分ける。due_dateには本人に適用される確認済み期限を入れ、一般日程を無条件にコピーしない。
4. 年額と各期を別債務として二重登録しない。1請求に複数期がある場合、原本本文に各期の金額と期限を記録し、due_dateは次の未払期の期限とする。完了時は最終期限を残す。
5. 予定納税・源泉徴収等を差し引いた精算額から、同じ額をもう一度減らさない。請求の対象が不明な場合は確認する。
6. 未確認はnull。見込みは年別ページに算定根拠・確認日つきで記録し、確定債務に混ぜない。
7. 年別ページから請求原本へ相対リンクする。複数年にまたがる請求も原本は1つ。年別集計では期別・実際の支払日で振り分け、請求総額を両年に重複計上しない。
8. 更新後は`make ledger-check`。`make ledger-summary`は全期間の確定請求の残高であり、年別支払い集計ではない。`make fava`で画面を確認する。金額のない計画はBeancount・Favaには計上されない。

支払い履歴は[金融の共通ルール](../README.md)に従う。国保・年金の実際の支払額と控除用資料も記録する。[国民年金の公式案内](https://www.nenkin.go.jp/service/kokunen/hokenryo/hokenryo.html)。
